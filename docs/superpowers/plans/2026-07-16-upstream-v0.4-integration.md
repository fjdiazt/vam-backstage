# Upstream v0.4 Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge current `upstream/master` into fork `develop` on a dedicated branch while preserving upstream v0.4 behavior and fork-only features.

**Architecture:** Create `merge/upstream-v0.4` from `develop`, perform a real merge from `upstream/master`, and resolve shared conflicts to upstream's refactored architecture as a baseline merge commit. Replay or port fork-only behavior in reviewable follow-up commits; use upstream changelog items plus fork feature tests as acceptance criteria.

**Tech Stack:** Git, Electron, React 19, Zustand, SQLite, Vitest, ESLint, Prettier, electron-vite.

## Global Constraints

- Work in current worktree; do not create another worktree.
- Never modify `master`; `upstream` remains fetch-only.
- Preserve existing user databases through additive/idempotent migrations.
- Preserve upstream dependency graph, drag/drop import, remote mode, smart search, Wishlist, Hub interactions, virtualization, and single-instance behavior.
- Preserve fork-only Hub paged mode, infinite-scroll paging, hidden resources, BrowserAssist hidden/label integration, mouse page navigation, and package alias.
- Prefer upstream implementations where both branches independently added persistence, Wishlist, back-to-top, paused downloads, or non-ASCII downloads.
- Commit the upstream baseline after all conflict markers are removed, then restore fork-only behavior in focused follow-up commits.
- Intermediate baseline may fail obsolete/local-only tests; final branch may not.

## Upstream Acceptance Matrix

- Dependency tooling: interactive dependency graph; disabled/offloaded dependency warnings; one-click enable; per-missing-dependency Hub Install; dependency search retaining parent context.
- Import: drag/drop `.var` files or folders; local and remote-library copies.
- Wishlist: upstream card/detail pins, dedicated gallery, search/filters/sorting, offline snapshots, Hub favorites/bookmarks import. Do not restore fork Wishlist unless manual testing rejects upstream behavior.
- Search and filters: plain terms plus `@author`, `#tag`, `%label`, `-`/`!` exclusions; `favorite`; custom Hub tags; trimmed Hub search; non-commercial-use license filter; reliable search clearing.
- Hub interactions: signed-in ratings/reactions/favorites/bookmarks; clickable dependencies; manual Hub linking; Previous/Next and arrow navigation; editable addresses; author-filter jump to Hub; republished-link refresh; smooth infinite loading; system proxy support.
- Views: mounted instant switching; virtualized galleries; row/column keyboard navigation; back-to-top; thumbnail arrow navigation; recently-installed grouping; persisted window bounds.
- Packages: subfolders; BrowserAssist/Saves offload directories; loose files; custom labels; update inheritance for category/labels/hidden/favorite; non-Latin downloads; fast bulk actions; reliable multi-select context actions; removal freeze fix.
- Extracted content: source tracking and badge; follows package disable/remove; re-extraction; appearance/clothing extraction; legacy-look conversion; extracted checkmarks.
- Automation: bundled hair/pose/clothing auto-hide rules; dependency-content hide/unhide when setting changes.
- Runtime: client-server mode; second-launch focus; faster Windows startup; reliable update checks; macOS installer/updater fixes; disable-warning and table-layout fixes.
- Manual branch test must cover Wishlist behavior before any fork Wishlist code is considered for restoration.
